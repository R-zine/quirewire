# Milestone M09 — Soak, observability, and release candidate

Milestone: M09
Result: **PASS: PHYSICAL**

## Acceptance scope

The final owner-approved M9 gate contains 10 required scenarios: 20 sequential
text/PDF jobs, a 20-page PDF, USB disconnect/reconnect while idle, VM crash,
Windows Spooler restart, owned guest/CUPS restart, loopback-port conflict,
second-instance rejection, simulated low-disk refusal, and cold start.

After the core soak and recovery checks consumed substantial paper, the owner
removed seven redundant or paper-intensive repeats from the M9 gate. `SPEC.md`,
the acceptance recorder, and release documentation now list normal-app repeat,
USB-during-print, host reboot, sleep/resume, no-paper, uninstall/reinstall
repeat, and UI-closed repeat as **deferred, non-gating, and NOT TESTED in M9**.
They are not represented as passing. Applicable M0/M5, M6, and M8 physical
evidence remains unchanged because M9 changed only diagnostics, tests, and
documentation—not product binaries.

Final ignored acceptance record `20261030T164318096Z-m9-acceptance.json`:
**PASS: PHYSICAL**, with no missing required scenario and matching evidence

## Implementation

- Added deterministic one-page text/PDF and 20-page numbered PDF generation
  with owned manifests and collision refusal.
- Added a real application soak harness. Text uses Windows Notepad's registered
  `/pt` route; PDF uses an owner-local, Authenticode-valid portable SumatraPDF
  with explicit queue selection. Each submission is correlated with a new CUPS
  job over the existing loopback-only SSH path. Printer inventory and the
  Windows default are compared before and after.
- Added redacted baseline/final metrics for the exact installed agent and exact
  VBoxHeadless process owning the configured loopback endpoint. The collector
  excludes USB serials, command lines, environment, window titles, and file
  contents.
- Added exact-ownership recovery diagnostics for cold start, hard VM crash,
  owned guest/CUPS restart, port conflict, Spooler restart, singleton rejection,
  and non-destructive low-disk guard behavior. VM mutations require the manifest
  UUID plus both live VirtualBox ownership values.
- Added optional owner-timed USB, sleep, no-paper, and host-reboot diagnostics.
  These scripts remain available despite their removal from the bounded gate.
- Fixed USB recovery timing to begin at observed USB loss rather than when the
  harness starts waiting for the owner. The existing idle-USB evidence contains
  transition timestamps, so acceptance derives its 72.860-second recovery from
  detected loss to observed Ready without rewriting physical evidence.
- Added a hash-verifying scenario recorder and aggregate acceptance recorder.
  Software/CUPS completion can never set a paper result; physical rows require
  explicit owner confirmation.
- Added end-user usage/troubleshooting, developer, security, licensing,
  limitations, release-checklist, and M9 acceptance documentation plus an M9 CI
  safety step.

## Failed experiment retained as a finding

An initial Win32 RAW-spool experiment was rejected. Windows jobs 9–12 reached
`Complete/Retained`, but no corresponding jobs reached guest CUPS and the owner
reported that nothing printed. Those jobs are not acceptance evidence, and the
temporary RAW harness was removed. The successful replacement uses actual
application paths: Notepad `/pt` reached CUPS and printed, as did signed
SumatraPDF. This confirms again that Windows spooler completion alone is not
physical or even downstream-CUPS proof.

## Physical and recovery evidence

The owner explicitly confirmed:

- all 20 alternating application jobs printed as distinct, legible, ordered
  sheets with no missing or duplicate jobs;
- the numbered 20-page PDF printed all pages in order without loss or
  duplication;
- diagnostic pages printed after cold start, exact owned-VM hard crash,
  owned guest/CUPS restart, loopback-port conflict recovery, and the scoped
  15-second Windows Spooler restart;

  same printer restored Ready, and the recovery page printed.

Software-only required rows also passed: a second agent was rejected while the
original PID remained, and a threshold above actual free space refused before
submission without filling disk or creating a print job.

Measured recovery times were 62.260 seconds for cold start, 72.691 seconds for
VM-crash recovery, 65.616 seconds for owned guest/CUPS restart, 52.483 seconds
for port-conflict repair, 72.860 seconds from observed USB loss to Ready, and
3.048 seconds after the Spooler service restarted. Every required recovery was
below the 180-second reference target.

## Security, licensing, and remaining release limits

- Generated host evidence, SSH material, portable test tool, USB identity, and
  configured appliance remain ignored and unbundled.
- CUPS and diagnostics stayed loopback-only. Recovery scripts compare printer,
  default-printer, and VM inventories and never remove drivers, ports, unrelated
  queues, or unrelated VMs.
- The Brother driver/appliance remains owner-local because redistribution rights
  are not established.
- Public production signing/timestamping is still **NOT TESTED** because no
  production certificate is available. The current development installer is
  unsigned and is not a public release artifact.
- Deferred M9 stress repeats are documented in `docs/m9-acceptance.md` and
  `docs/known-limitations.md`; they are optional and unclaimed.
