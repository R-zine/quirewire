# Milestone M2 report

Milestone: **M2 — Rust workspace, contracts, CLI, fakes**  
Report date: **2026-10-28**  
Result: **PASS: SOFTWARE ONLY**

## Implementation

- Created an edition-2024 Cargo workspace pinned to Rust 1.94.0 with domain,
  core, IPC, agent-handler, CLI, and the three specified provider boundary crates.
- Defined the required error taxonomy with stable codes, retry classification,
  actionable display text, and context-free summaries safe for telemetry.
- Added separate typed states for hypervisor, guest, USB, CUPS, and Windows queue,
  with derived overall phases: `NotConfigured`, `Provisioning`, `Starting`,
  `WaitingForUsb`, `Connecting`, `Ready`, `Degraded`, `Error`, and `Stopping`.
- Defined `Hypervisor`, `UsbAccess`, `GuestPrinting`, `WindowsPrinting`, and
  `Startup` traits. Destructive VM operations require a typed `OwnedVm`; USB
  identity retains VID:PID plus optional serial while display/debug output redacts
  the serial.
- Implemented an explicitly labeled, stateful in-memory fake for every provider
  contract. Fake CUPS completion remains `CompletedByCups` and never becomes
  `PhysicalOutputConfirmed` without an explicit source.
- Implemented a framework-free controller, state machine, bounded exponential
  retry policy, fake clock, and JSON-line structured trace events with field-level
  redaction. Tracing is opt-in through `--trace`; default CLI output contains no
  diagnostic trace stream.
- Added protocol version 1 with `GetStatus`, `Doctor`, and `Help`, plus an
  in-process transport. The framework-free agent request handler owns the
  controller, and `quirewirectl` is a client of that API rather than importing
  provider implementation crates.
- Implemented `quirewirectl status`, `doctor`, and `help` using only the fake
  provider. Output says `fake-in-memory` and `physical_output: not_inferred`.
- Added provider contract tests, state transition tests, fake-clock retry tests,
  error/redaction tests, protocol tests, CLI tests, rustfmt/clippy configuration,
  and Windows GitHub Actions CI.
- Wrote ADR-001 for Rust/Tauri versus Go/Wails and ADR-002 for provider/ownership
  boundaries. ADR-001 distinguishes measured M1 VM data from unmeasured controller
  overhead.
- Did not implement a real VirtualBox/CUPS/Windows provider, named-pipe transport,
  persistent agent executable, guest appliance automation, or Tauri UI.

## Known failures, security, and licensing notes

- The provider crates are compile-time boundaries, not implementations. A green
  fake doctor does not indicate that VirtualBox, CUPS, USB, or Windows printing is
  currently reachable.
- M2 uses an in-process protocol client. The per-user ACL-restricted Windows named
  pipe and standalone background agent belong to M6.
- The state machine and retry executor are synchronous because M2 performs no real
  I/O; async behavior will be added only where a real provider requires it.
- Trace fields are public or sensitive by construction; USB serial `Display` and
  `Debug` output omit/redact the serial. Raw provider output must remain outside
  telemetry until classified.
- The crates are marked `publish = false`. No project source-license choice or
  redistribution right is asserted by M2; third-party/provider licensing remains
  subject to the later packaging review.
- Rustup initially could not write its user temp directory from the sandbox. The
  pinned formatter/clippy components were verified with approved host-level
  toolchain access. This is an execution-environment permission issue, not a
  product runtime dependency.
