# Milestone M05 — Windows IPP printer integration

Milestone: M05  
Result: **PASS: PHYSICAL**

## Implementation

- Added a concrete Rust `WindowsPrinting` provider backed by the installed
  Windows PrintManagement module. Subprocesses use argument vectors, bounded
  timeouts and a versioned base64-safe response protocol.
- Added exact detection of `Add-Printer -IppURL`, PrintManagement version,
  spooler state, target queue, driver, WSD port, default status and persisted
  ownership.
- Added marker-owned, idempotent install/removal. Collision, ownership drift,
  non-loopback endpoints, unexpected drivers and default-queue removal are
  refused. No printer driver or port is deleted.
- Added `quirewirectl printer install`, `status`, `test-page`, and `remove`
  through the versioned agent request API. Test-page output explicitly separates
  Windows spooler acceptance from CUPS and physical output.
- Added guided Windows Settings fallback for builds without `-IppURL`; it never
  proposes a Brother Windows driver.
- Added Windows diagnostics, deterministic Notepad/PDF fixtures, safe physical
  acceptance recorder, software test suite and owner checklist.

## Security and limitations

- Ownership is established by a per-user record plus exact live queue name,
  endpoint, driver, WSD port and unique comment. M6 will add hardened persistent
  agent state/ACLs; M5 does not implement startup or named-pipe IPC.
- Removal deliberately retains Windows-created driver and port objects and the
  ownership record for audit/idempotence.
- A spooler submission correlation ID is diagnostic evidence only. Windows may
  drain a small test job before its spooler job ID can be observed.
- No vendor binary is added or redistributed in M5.
