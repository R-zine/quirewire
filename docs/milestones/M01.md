## Implementation

- Built a manually provisioned, minimal Debian 13.7 x86_64 VM in VirtualBox
  7.2.22 with 1 vCPU, 768 MiB RAM, a 10 GiB dynamic disk, no desktop, headless
  frontend, and zero Extension Packs.
- Bound all lifecycle work to owned VM UUID
  `fd91fe56-f746-4884-9aa7-3b972882183a`; the preserved M0 VM was not modified.
- Configured NAT loopback forwards `127.0.0.1:2222` to guest SSH and a dedicated
  M1 endpoint `127.0.0.1:8632` to guest CUPS. The earlier 8631 M0 endpoint/queue is
  retained for audit but is not reused for M1 because its WSD port caches the M0
  printer UUID. CUPS is not exposed directly on the host LAN.
- Added an exact VirtualBox USB filter for Brother `04f9:0567` plus the selected
  serial. The serial is retained only in local ignored configuration/evidence and
  omitted from committed documents.
- Installed CUPS, multilib dependencies, Brother's official DCP-L2600D Debian
  driver, and Brother's Debian 11+ legacy USB patch. Created and shared guest queue
  `DCPL2600D`, then verified IPP attributes and formats through the NAT endpoint.
- Added read-only, serial-redacting M1 host and guest diagnostics, stage-specific
  physical print fixtures, a marker-owned loopback-only M1 IPP queue manager, a
  hard-gated acceptance recorder, and a complete owner-executable
  clean-boot/reconnect/host-reboot checklist.
- Corrected an M0 CUPS-sharing helper race discovered on Debian: it now waits for
  the scheduler after `cupsctl` and sets the queue share flag before enabling
  global sharing. Its existing ownership/rollback rules remain intact.
- Did not begin the Rust workspace, managed appliance, product CLI/agent, or GUI.

## Known failures, security, and licensing notes

- M1 passed only after every required page was observed on paper and correlated
  with CUPS jobs; completed job state alone was never treated as physical proof.
- A Microsoft IPP/WSD port cannot safely be repointed to a different CUPS
  `printer-uuid` merely by placing another server behind the same forwarded URL.
  M1 therefore uses its own 8632 endpoint and marker-owned queue while preserving
  the M0 queue and port.
- Snapshot resume did not recapture USB, while clean boots and real physical
  reconnects did. The product reconciler must distinguish saved-state restoration
  from clean boot and provide bounded remediation.
- The M0 and M1 Windows queues are separately marker-owned. Only the failed M0
  test job was removed after its evidence was captured; no unrelated queue, port,
  driver, default-printer setting, VM, filter, or user data was removed.
- Host diagnostics omit USB serials. Generated evidence remains ignored because
  it may contain local paths, user/machine names, document names, and raw logs.
- SSH is key-only for the ordinary guest user; password authentication and root
  SSH are disabled. Final console checks showed both `root` and `quirewire`
  password states locked. The four exact ignored provisioning credential/log files
  were permanently removed after path validation; the secrets directory is empty.
- Brother packages were downloaded after accepting Brother's terms and are not
  redistributed. The legacy patch's filename/metadata version mismatch is
  recorded. Any product bundling decision remains deferred to licensing review.
- VirtualBox base components are GPLv3; no Extension Pack was installed.
- M1 deliberately has no Windows login autostart. Host-reboot recovery therefore
  includes a documented manual VM start; product autostart belongs to M6.
