# Milestone M0 report

Milestone: **M0 — Proof of actual Windows to Linux printing**

## Implementation

- Created the M0-only repository skeleton while explicitly deferring the Rust
  workspace, background agent, VM appliance, and Tauri UI to later gated
  milestones.
- Added read-only Windows diagnostics for OS/build, `Add-Printer -IppURL`
  capability, spooler, protected-print policy, printer/driver/port metadata,
  print jobs/events, endpoint reachability, and USB/PnP IDs.
- Added a marker-owned Windows IPP registration wrapper. It defaults to a dry run,
  verifies the exact `Microsoft IPP Class Driver`, refuses queue-name collisions,
  and removes only a queue whose name/comment/port/driver match its ownership
  record. Live IPP registration showed that Windows can replace the requested
  comment with server metadata, so the wrapper now reapplies and verifies its
  ownership comment or removes only the queue created by that failed invocation.
- Added deterministic text, one-page PDF/image, and optional two-page color/duplex
  test-document generation. The PDFs contain raster image XObjects and computed
  cross-reference tables.
- Added read-only Linux collection for OS/package architecture, CUPS versions and
  configuration, USB IDs, queue/driver filters, IPP attributes, jobs, listeners,
  and recent logs.
- Added opt-in Linux baseline submission and reversible CUPS sharing. The sharing
  script never calls `--remote-any`, will not create/delete a queue, refuses to
  expose another queue when enabling global sharing, and restores only recorded
  values when live state still matches M0 ownership expectations.
- Added an acceptance recorder that cannot emit `PASS: PHYSICAL` without explicit
  Linux/text/PDF passes, the exact inbox driver, endpoint/application/job metadata,
  and the human confirmation switch.
- Added the complete owner-executable procedure and bounded cleanup in
  `docs/feasibility.md`.
- Built an ignored, owner-authorized Fedora 44 feasibility guest after QEMU could
  enumerate but not configure the USB device. Installed VirtualBox `7.2.22` core
  plus USB support only (zero Extension Packs), captured only `04F9:0567`, installed
  Brother's official `dcpl2600dpdrv-4.1.0-2.i386.rpm`, and exposed CUPS only through
  loopback NAT forwarding.

## Known failures, security, and licensing notes

- M0 passed only after the owner explicitly confirmed the Linux USB baseline and
  Windows normal-application text/PDF sheets.
- An accepted/completed Windows or CUPS job is not evidence that paper printed.
- CUPS is scoped to a trusted local subnet. The tooling refuses `--remote-any`; any
  firewall exception must be limited to the single Windows IPv4 and removed after
  the POC. The Fedora checklist uses a non-permanent firewalld rich rule with a
  two-hour automatic timeout.
- Protected Print Mode is observed but never changed automatically.
- Generated evidence is ignored because it can contain machine names, addresses,
  USB serials, job/document names, and user names.
- The Brother RPM is unsigned but came from Brother's official post-EULA download
  endpoint; its digest and SHA-256 are captured. It remains only in ignored local
  evidence and is not committed or redistributed.
- Oracle VirtualBox base components are GPLv3; no separately licensed Extension
  Pack was downloaded or installed.
- No unrelated Windows printer, port, driver, CUPS queue, VM, firewall rule, or user
  data was changed or removed. The only new queue and VM are explicitly named M0
  resources with ownership evidence.
