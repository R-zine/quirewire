# Milestone M11 — Driverless scanning for all consumers

Milestone: M11

Result: `PASS: PHYSICAL`

Accepted: 2026-11-02 on the owner’s Brother DCP-L2600D, Windows host, and
Android phone.

## Delivered

- Added the `provider-scan` crate and protocol v7 scanner status/capability
  model. The agent, CLI, desktop, diagnostics, and fake client share the same
  metadata-only IPC; scan document bytes never enter PrintBridge IPC, logs,
  state, or diagnostic exports.
- Added bounded eSCL capability parsing with connection/read timeouts, a
  512 KiB response limit, status/content-type validation, and rejection of
  DTDs/entities.
- Added the desktop Scan screen and fixed loopback scanner launcher. The UI
  offers the approved LAN IPv4 as the official Mopria manual-add fallback.
- Added distinct marker-owned VirtualBox loopback/LAN eSCL forwards, separate
  TCP 8645 approval, and exact-program/interface/subnet firewall management.
  LAN scanning remains off without explicit approval.
- Added `_uscan._tcp` publication with the official AirSane v2 compatibility
  fields: `txtvers`, `vers`, `pdl`, `ty`, `note`, lowercase `uuid`, `rs`, `cs`,
  `is`, `duplex`, and `adminurl`. Guest AirSane mDNS remains disabled so only
  the Windows agent advertises on the approved LAN.
- Pinned owner-local Brother `brscan5` 1.7.0-0 and AirSane commit
  `08ff4d798d718e2e50ef805404ddef82f6d03cc1`. The GPL source patch for
  upstream issue #132 releases AirSane’s startup-only SANE session before
  acquisition so Brother’s backend can open the device. No Brother package,
  AirSane binary, VirtualBox installer, or appliance is bundled.
- Added ownership-checked offline guest migration/repair, eSCL and DNS-SD
  diagnostics, scan approval management, software tests, licensing/security
  notes, troubleshooting, usage guidance, and a no-paper physical checklist.
- Added a lifecycle migration that removes only the exact non-default,
  marker-owned M0/M1 queues. Modified, unowned, or default queues and all ports
  and drivers are preserved.
- Fixed the installer lifecycle to use native 64-bit PowerShell and
  `ProgramW6432`. This prevents a 32-bit NSIS hook from resolving VirtualBox
  under `Program Files (x86)`. Hook outcomes and bounded error messages are
  retained in owner-local lifecycle logs.
