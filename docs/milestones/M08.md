# Milestone M08 — Installer, startup, repair, and uninstallation

Milestone: M08
Result: **PASS: PHYSICAL**

## Implementation

- Added a Tauri NSIS packaging overlay that produces a per-user Windows 11 x64
  installer without changing the ordinary M7 development configuration. It
  packages the desktop, headless agent, CLI, fixed provider/lifecycle scripts,
  guest build source, and operator documentation.
- Kept VirtualBox, the Extension Pack, Debian installation media, Brother
  packages, configured appliance, SSH keys, and USB identity out of the
  installer. Prerequisite diagnostics guide the owner to supported VirtualBox
  7.x and disclose WebView2, network, 12 GiB disk, 768 MiB guest RAM, and
  whole-device USB requirements.
- Added fixed NSIS install, upgrade, and uninstall hooks. The protected
  `quirewire.m8.installation.v1` manifest binds the owner SID and exact
  install/data roots, task, queue state, and VM disposition.
- Added narrowly scoped queue elevation. A read-only status/ownership check
  runs first; UAC is requested only if the exact marker-owned Microsoft IPP
  queue must be created or removed. The persistent agent and
  `\QuireWire\Agent` task always run with a limited interactive token.
- Added deterministic repair and uninstall. Cleanup refuses identity drift,
  never removes printer drivers/ports or VirtualBox itself, preserves migrated
  M4 appliances, and may delete a VM only when the manifest says
  `installation-owned` and both live extradata ownership values still match.
- Added installed-resource discovery for the Rust Windows providers. Source
  paths remain only the final development fallback.
- Made release agents Windows GUI-subsystem processes and applied
  `CREATE_NO_WINDOW` to PowerShell and VBoxManage children, preventing the
  product's background process tree from flashing console windows.
- Added explicit unsigned-development and certificate-thumbprint signed build
  paths, a manual GitHub Actions installer workflow, prerequisite/diagnostic/
  acceptance tools, and install/licensing documentation.

## Terminal-flash investigation

The owner reported a terminal window flashing while M8 work was active. The
exact QuireWire task was disabled and all QuireWire agent processes were
stopped; the flashing continued. A bounded 75-second name/path-only trace with
no QuireWire task or process recorded 167 starts: 65 `conhost`, 32 `git`, 27
`docker`, 15 `OpenConsole`, 14 `WindowsTerminal`, 13 `whoami`, and one Chrome.
Terminal/OpenConsole starts repeated at roughly five-second intervals. This
rules out QuireWire as the trigger and points to the active development host
environment; the trace did not collect command lines and therefore does not
claim an exact unrelated parent. No Terminal or Docker settings were changed.

The product was nevertheless hardened: the installed release agent has the
Windows GUI subsystem and all background provider children use
`CREATE_NO_WINDOW`.
