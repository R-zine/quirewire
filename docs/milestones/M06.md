# Milestone M06 — Headless supervisor, IPC, and recovery

Milestone: M06
Result: **PASS: PHYSICAL**

## Implementation

- Added a standalone, framework-free `quirewire-agent.exe`. No Tauri crate,
  webview, tray process, or desktop launch is involved.
- Added protocol v4 with exactly the required typed commands: `GetStatus`,
  `DiscoverDevices`, `BeginSetup`, `Start`, `Stop`, `Restart`, `TestPrint`,
  `GetDiagnostics`, and `Repair`. Unknown fields/commands and frames over 64 KiB
  are rejected; no arbitrary execution command exists.
- Added a Windows named-pipe transport scoped to the current owner SID. It uses
  a protected owner-only DACL, rejects remote clients, and uses the OS
  first-pipe-instance flag for process singleton enforcement.
- Added request-ID response caching so a repeated request cannot duplicate a
  print or lifecycle mutation within the bounded cache window.
- Added an exact-ownership supervisor for the accepted M4 VM, selected
  serial-bearing USB device, CUPS queue, and M5 Windows queue. It tracks each
  component separately, reconciles without a UI, detects a stopped spooler or
  loopback port conflict, captures USB after reconnect, and uses bounded
  2/4/8/16/30-second failure backoff with a 10-second healthy observation
  interval.
- Added immutable, atomically renamed state generations. Every generation
  repeats the exact owned VM/USB/endpoint/queue identities and desired state;
  no partial file or ambiguous display name can authorize mutation.
- Added structured JSONL events and redacted diagnostics. USB serial values are
  persisted only in the ACL-protected configuration/state and do not appear in
  IPC device output, logs, or diagnostic bundles.
- Added a `Startup` provider backed by an exact `\QuireWire\Agent` Task
  Scheduler entry: current user, Interactive Token, Limited, hidden,
  `IgnoreNew`, and start-at-logon. Exact action, arguments, owner SID after
  Windows account-name normalization, and ownership description are collision
  guards.
- Converted M6 CLI commands to real named-pipe clients. Earlier M3/M5 direct
  commands remain only as milestone/debug tooling.
- Added owner-protected configuration derivation from matching M4 software and
  physical acceptance records, a diagnostics collector, acceptance recorder,
  software suite, and physical recovery checklist.

## Security and limitations

- The single reviewed unsafe module exists only to pass an explicit Windows
  security descriptor to Tokio's named-pipe creation API. Every other crate
  retains unsafe-code denial/forbid rules.
- M6 does not expose SSH commands or arbitrary guest service control. `Repair`
  may restart only the exact owned VM when CUPS remains unhealthy.
- First-time Windows queue creation can still require UAC on this host. The M5
  owned queue already exists; the non-elevated agent never self-elevates.
- Logoff behavior is explicit: the Interactive Token task's process ends with
  the user session. Pre-login printing is not promised. At next logon the task
  starts one agent, which loads the last complete state generation and
  reconciles.
- Final observation: exactly one agent, all components `ready`, two owned task
  triggers with watchdog interval `PT1M`, Microsoft IPP Class Driver intact,
  and `OneNote (Desktop)` still the default printer. The selected USB serial was
  absent from both the final diagnostics bundle and JSONL log.
