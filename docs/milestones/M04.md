## Implementation

- Added a version-pinned unattended Debian 13.7 amd64 appliance build using a
  VirtualBox VISO overlay, preseed, a 10 GiB dynamic disk, one vCPU, and no GUI.
  Debian installation receives 1 GiB because its low-memory prompt occurs before
  the preseed; every exported/runtime VM is reset to the specified 768 MiB.
- Split the build into a base OS+CUPS OVA and an owner-local configured OVA. The
  base contains no Brother package. Official packages remain ignored external
  inputs and are never committed or silently downloaded.
- Pinned the Debian ISO hash, snapshot timestamp, direct package versions,
  Brother package metadata/hashes/source URLs, installed PPD hash, D-Bus runtime
  dependency, and open-driver version.
- Added open `brlaser` and official Brother driver media workflows. The open path
  refuses queue mutation if the pinned driver does not advertise DCP-L2600D. The
  official path verifies package name, embedded version, architecture and hash,
  installs the legacy USB patch first, validates the PPD, and records selection.
- Added idempotent base repair and driver-media application. Repair refuses to
  change a known-good driver mode or package hashes and owns only intentionally
  named queue `QuireWire_DCP_L2600D`.
- Configured CUPS without remote admin or `remote-any`, key-only loopback SSH, a
  locked unprivileged `quirewire` account, multi-user target, log rotation,
  periodic health, bounded diagnostics, and USB-serial redaction.
- Added marker-owned build and acceptance harnesses. Build VMs are marked before
  later mutation and deleted only after exact live-marker validation. Acceptance
  imports a fresh configured OVA, reapplies identical media, removes media,
  verifies 768 MiB headless runtime, waits for protocol readiness, probes IPP,
  collects diagnostics, and submits one tokened page.
- Replaced the CUPS placeholder with a bounded, dependency-free binary IPP
  adapter for health, queue status/listing, job listing/submission, and safe
  diagnostics. It supports both HTTP `Content-Length` and chunked persistent
  responses and never equates CUPS completion with physical output.

## Findings resolved during implementation

- Debian's 768 MiB low-memory dialog precedes preseeding; install-time memory is
  now distinct from exported/runtime memory.
- Installer-chroot `systemctl is-active` can report success while ignored;
  live CUPS configuration is deferred to boot/repair.
- `--no-install-recommends` omitted D-Bus, which unprivileged service health
  requires; exact snapshot version 1.16.2-2 is now a direct base dependency.
- PowerShell's automatic `$Matches` is case-insensitive and collided with a USB
  collection variable; both host harnesses now use an unambiguous name.
- VirtualBox and OpenSSH write successful progress/warnings to stderr; wrappers
  now judge native exit codes instead of PowerShell error-stream promotion.
- Real CUPS uses chunked persistent HTTP for IPP. The provider now decodes
  bounded chunks and stops on declared message completion rather than socket
  closure.
- IPP `requested-attributes` is multi-valued: the name is encoded once and later
  values use zero-length names. The provider follows that encoding and its live
  state now agrees with `lpstat`.
- NAT becomes connectable before CUPS is protocol-ready. Acceptance now performs
  a bounded 180-second real-IPP readiness loop instead of trusting TCP alone.

## Security and licensing notes

- CUPS and SSH forwards bind only to `127.0.0.1`; the guest has no bridged NIC.
- SSH password, keyboard-interactive, empty-password and root login are denied.
- The configured OVA and Brother `.deb` files are owner-local only pending
  redistribution/licence review. Git tracks no `.deb`, ISO, OVA, OVF, VDI,
  VMDK, private key, generated driver medium, or USB serial.
- Software retains the honest `physical_output=not_inferred` state. Physical
  success comes only from the separate owner response.
