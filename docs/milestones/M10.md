# Milestone M10 — On-demand trusted-LAN sharing

Milestone: M10

Result: `PASS: PHYSICAL`

The product objective changed after M9: the desktop now owns the agent/VM
lifetime, nothing starts at Windows login, and an active app shares the selected
printer to trusted same-subnet devices through scoped IPP plus DNS-SD.

## Implemented changes

- Protocol v6 adds LAN state (including Windows category), desktop heartbeat and
  graceful shutdown.
- The desktop launches the agent hidden with `--on-demand`, renews a bounded
  lease, starts the bridge, hides window-close to tray, and makes explicit Exit
  stop the VM/agent rather than abandoning them.
- The exact legacy login task is removed and never recreated.
- Windows policy requires an explicit interface alias plus canonical directly
  attached IPv4 subnet. Firewall rules are marker-owned and constrained to the
  exact program, protocol, port, approved interface and remote CIDR. They cover
  `Private,Public` only so the owner's Public-category `Ethernet 3` adapter can
  serve `192.168.100.0/24`; no other Public scope is approved.
- VirtualBox owns a separate M10 LAN NAT rule with exact extradata and collision
  refusal. The loopback Windows queue remains unchanged.
- DNS-SD advertises `_ipp._tcp` only on the selected interface using formats,
  UUID, URF, color and duplex values queried from CUPS. Oversized format lists
  are reduced to a truthful, prioritized subset within the DNS-SD TXT limit.
- The guest keeps remote administration disabled and permits remote access only
  to `/printers/PrintBridge_DCP_L2600D`. Reproducible provisioning applies that
  marker-delimited policy; the accepted pre-M10 VM was migrated through a
  validated offline clone with its original VDI retained for rollback.
- Configuration identity changes create a new immutable stopped state
  generation. Long desktop-triggered reconciliation refreshes the heartbeat
  lease on completion, preventing false shutdown after a slow cold start.
