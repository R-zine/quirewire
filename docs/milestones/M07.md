# Milestone M07 — Modern Tauri 2 desktop and system tray

Milestone: M07
Result: **PASS: PHYSICAL**

## Implementation

- Added a Tauri 2 Windows desktop process with a React/TypeScript frontend,
  high-DPI responsive layout, system/light/dark themes, keyboard-visible focus,
  reduced-motion handling, and explicit loading, error, and empty states.
- Added setup, live dashboard, recent activity/test print, diagnostics/export/
  repair, and settings/startup/about screens.
- Added a frontend `PrintBridgeClient` contract, an in-memory fake used only by
  tests and explicit browser-preview mode, and a real Tauri adapter with fixed
  commands.
- The desktop Rust crate links only `printbridge-ipc`. Every operation reaches
  the standalone agent through the protocol-v4 owner-only named pipe; the UI
  imports no VirtualBox, USB, CUPS, PowerShell, or Windows printing code.
- Added a Tauri tray with Open, Test page, Restart bridge, View diagnostics,
  and `Exit UI (engine keeps running)`. Closing the window hides it to the tray;
  exiting never sends `Stop`.
- Added a user-initiated, fixed-destination redacted diagnostic export under
  `Documents\PrintBridge`; the webview cannot choose arbitrary write paths.
- Added a restrictive CSP and a single window capability. The frontend uses no
  local/session storage, so credentials and driver downloads cannot be retained
  there.

## Security and limitations

- The desktop is an ordinary user client; it does not elevate or contain
  provisioning credentials.
- Diagnostic exports include local paths and the owner SID but deliberately no
  stored USB serial. Treat exports as private support data.
- Packaging/install/uninstall are M8 and are deliberately not implemented.
