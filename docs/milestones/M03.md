# Milestone M3 report

Milestone: **M3 — Real VirtualBox provider and USB selection**

Report date: **2026-10-28**

Result: **PASS: WINDOWS INTEGRATION + OWNER-GATED REAL USB**

## Implementation

- Implemented a real, standard-library-only `VBoxManage` provider. Commands use
  direct executable argument arrays rather than a shell, keep stdout/stderr
  separate, and are killed after bounded timeouts.
- Added installed-path discovery, version parsing, and an explicit support policy
  for VirtualBox 7.1–7.2. Unsupported versions and missing executables return
  actionable typed errors.
- Added real host-prerequisite diagnostics. The installed host reports VirtualBox
  7.2.22, hardware virtualization available, and 20 online processors.
- Implemented appliance import, state inspection, headless start, ACPI stop, and
  deletion. Lifecycle mutation always uses a canonical UUID and requires both
  matching live extra-data values:

  ```text
  PrintBridge/Schema=printbridge.m3.owned-vm.v1
  PrintBridge/Owner=<persisted marker>
  ```

- VM start uses `startvm <UUID> --type headless`. Start and stop are idempotent;
  recovery from VirtualBox's closed `aborted` state is allowed only after exact
  ownership validation. Deletion requires a stopped/saved exact owned VM.
- Implemented real host USB discovery and parsing, VID:PID plus serial matching,
  verified exact owned filters, live attachment checks, detach/reconnect recovery,
  device-busy/permission diagnostics, and safe filter removal.
- Serial-bearing devices can install a serial-matched owned filter while Windows
  reports the current connection busy, then capture on reconnect. Serial-less
  duplicates require an explicit current one-based selection and attach by host
  UUID without creating a broad filter.
- Added a provider-scoped opaque host handle to the USB domain model. Serial
  values remain redacted from `Display`, `Debug`, CLI inventory, traces, reports,
  and repository-tracked evidence.
- Bumped the typed in-process protocol to v2 and added `doctor`, `vm status`,
  `vm start`, `vm stop`, `usb list`, `usb attach`, and `usb release`. The CLI
  talks to the agent handler and does not import the provider crate.
- Added schema-validated M3 configuration loading from `--config`,
  `PRINTBRIDGE_M3_CONFIG`, or `%LOCALAPPDATA%\PrintBridge\m3.conf`. Mutation is
  refused without an exact configuration.
- Added a Windows integration harness that creates a full disposable clone,
  immediately marks it, removes inherited USB filters and host NAT forwards,
  retains guest NAT, proves a mismatched ownership marker is refused, waits on a
  temporary loopback-only CUPS readiness port plus a bounded guest settle, and
  exercises repeated lifecycle operations.
- Added the owner-gated physical USB checklist and M3 configuration/runbook. No
  Tauri UI, persistent agent, named pipe, CUPS provider, Windows queue provider,
  or M4 appliance work was started.

## Findings resolved during real integration

- Windows PowerShell 5.1 promotes successful `VBoxManage` progress written to
  stderr into `NativeCommandError`; the harness now evaluates the process exit
  code while capturing that stream.
- The M1 source finished ACPI as closed `aborted`; the harness accepts stable
  `poweroff` or non-running `aborted` as clone-source states and separately checks
  `list runningvms`.
- Disabling all cloned NICs delayed this guest's boot. The final harness keeps NAT
  but removes every inherited host-forwarding rule and adds one temporary
  loopback-only readiness port.
- This M1-derived guest ignores ACPI during a roughly 90-second post-CUPS boot
  job. The harness waits for CUPS plus that measured settle; the provider's
  shutdown assertion remains bounded at 60 seconds.
- Installed VirtualBox prints `Currently attached USB devices:` with different
  capitalization from the initial fixture. Parsing is now case-insensitive and
  covered by a regression test.
- Windows can claim the printer before direct attach. Busy serial-bearing devices
  now prepare only an exact owned filter and give actionable reconnect guidance.

## Security, safety, and licensing notes

- Raw provider output and private configuration may contain stable device
  identifiers and must not enter telemetry or tracked evidence.
- The M3 configuration is plaintext and must be treated as private. Atomic
  persistent state and per-user ACL enforcement belong to M6.
- The process adapter never invokes a command shell. Every command is an
  allowlisted provider operation with an argument vector and timeout.
- Filter removal matches the deterministic owned filter name and exact USB
  identity. A changed filter is refused; unrelated filters are preserved.
- No external Rust crate, driver, firmware, appliance, or redistributable binary
  was added. VirtualBox and Brother licensing/redistribution remain external to
  this source milestone.
